# 온휴 — 직원 연차 관리

관리자가 직원과 연차를 관리하는 한국어 프로그램입니다. **Windows 실행판은 Node.js 설치나 명령어 입력 없이 실행**할 수 있습니다. 로그인 없는 관리자용 로컬 버전이므로, 직원에게 공개하거나 인터넷에 배포하기 전에는 인증·권한 기능을 추가해야 합니다.

## Windows 프로그램 다운로드

**[Windows용 온휴 ZIP 다운로드](https://github.com/parksongyii-source/musical-broccoli/raw/refs/heads/main/downloads/onhyu-windows-x64-v0.3.0.zip)**

1. Windows 10/11 64비트 PC에서 ZIP을 다운로드하고 **압축을 모두 풉니다**.
2. `Onhyu.exe`를 더블클릭합니다.
3. 자동으로 열린 브라우저에서 직원을 등록하면 됩니다.

Node.js 설치, `npm` 명령, 인터넷 연결은 실행에 필요하지 않습니다. 처음에는 빈 직원 목록으로 시작합니다. 종료할 때 화면 아래 **프로그램 종료**를 누르세요. 실행 중 함께 열리는 작은 콘솔 창을 닫아도 종료됩니다. 브라우저 탭만 닫으면 프로그램은 계속 실행됩니다.

자료는 `%LOCALAPPDATA%\Onhyu` 폴더에 자동 저장됩니다. 백업하려면 프로그램을 종료한 뒤 이 폴더 전체를 복사하세요. EXE를 다시 다운로드해도 이 데이터 폴더를 유지하면 직원 자료는 남습니다. 전자서명이 없는 초기 실행판입니다.

실행판은 소스나 별도 패키지 없이 작동하도록 Node SEA로 제작합니다. 배포 파일에는 Node 및 번들 의존성의 라이선스 고지가 포함됩니다.

**0.3.0 업데이트:** 입사일을 입력하면 발생 연차가 자동 계산됩니다. 기존 프로그램을 종료한 후 새 EXE를 실행하세요. 기존 직원·휴가 기록은 그대로 유지하며, 이전 데이터베이스 형식은 갱신 전에 같은 폴더에 SQLite 백업을 생성합니다. 기존 직원도 자동 계산으로 전환하고, 과거 직접 부여한 일수는 기록을 보존하여 직접 설정으로 복원할 수 있습니다.

## 개발용 소스 패키지

[온휴 실행 패키지 ZIP 다운로드](https://github.com/parksongyii-source/musical-broccoli/raw/refs/heads/main/downloads/onhyu-leave-manager-0.1.0.zip)

압축을 풀고 `onhyu/처음사용.txt`를 확인하세요. Windows 설치형 EXE는 아니며 **Node.js 24**가 필요합니다. 빌드된 화면이 포함되어 있어, 압축을 푼 `onhyu` 폴더에서 터미널을 열고 아래 명령을 각각 실행하면 됩니다.

```sh
npm ci
npm start
```

실행 메시지가 나오면 브라우저 주소창에 `127.0.0.1:3001`을 입력하세요. 첫 설치에는 인터넷 연결이 필요합니다. 실행 패키지에는 기존 직원 데이터나 인증 정보가 포함되지 않습니다.

GitHub의 **Code → Download ZIP**으로 소스 전체를 받은 경우에는 `npm ci`, `npm run build`, `npm start` 순서로 실행하세요. 아래 `/workspace` 경로는 클라우드 개발 환경의 예시입니다. 개인 PC에서는 압축을 푼 폴더에서 실행하면 됩니다.

## 시작하기

Node.js 24가 필요합니다. 사용한 버전은 `.node-version`에 기록되어 있습니다.

```sh
cd /workspace/musical-broccoli
npm ci
npm run dev
```

개발 화면은 포트 5173, API는 포트 3001에서 실행됩니다. 두 서버는 기본적으로 `127.0.0.1`에서만 연결을 받습니다. `Ctrl+C`로 함께 종료합니다.

빌드한 화면을 API 서버에서 제공하려면 다음을 사용하세요.

```sh
npm run build
npm start
```

이 경우 포트 3001에서 화면과 API를 함께 제공합니다. 실행 중인 다른 API 서버가 있다면 먼저 종료하세요.

## 기능과 계산 기준

- 직원 등록·수정, 입사일 기준 연차 자동 계산 및 직접 조정
- 연차·오전 반차·오후 반차 신청과 승인·반려·취소
- 직원별 사용·대기·잔여 연차 조회, 휴가 목록과 달력
- 토요일·일요일을 제외한 사용 일수 계산, 반차는 평일 하루에 0.5일
- 승인 대기 중인 일수도 예약하여 초과 신청 방지
- 동일 직원의 중복 휴가 방지. 같은 날 오전·오후 반차는 각각 신청 가능

연차 관리 기간은 **입사 기념일부터 다음 입사 기념일 전날까지**입니다. 예를 들어 2023년 7월 12일 입사자의 2026년 11월 5일 기준 기간은 2026년 7월 12일~2027년 7월 11일입니다. 조회 기준일을 바꾸면 각 직원에게 해당하는 기간을 함께 조회합니다. 2월 29일 입사자는 평년에는 2월 28일을 기념일로 사용합니다.

일반 법정 기준으로 입사일과 조회 기준일을 사용해 자동 산정합니다.

- 1년 미만: 완료한 근무 월마다 1일, 최대 11일. 아직 발생하지 않은 월차는 미리 사용할 수 없습니다.
- 1년 이상: 기본 15일. 3년 근속부터 2년마다 1일 가산하여 최대 25일입니다. 만 1·2년은 15일, 만 3·4년은 16일, 만 5·6년은 17일입니다.
- 개근 및 연간 출근율 80% 요건을 충족한 것으로 가정합니다. 실제 근태 정보는 수집하지 않으므로 예외나 회사 규정은 직원 수정의 직접 설정으로 조정하세요.
- 월말 입사자는 원래 입사일을 기준으로 짧은 달의 마지막 날에 월차가 발생합니다. 예를 들어 1월 31일 입사자는 2월 28일(윤년은 29일), 3월 31일에 각각 발생합니다.
- 입사 1주년이 되면 새 연차 기간의 15일로 전환합니다. 이전 기간의 남은 일수는 자동 이월하지 않습니다.

잔여 연차는 해당 기간의 발생·부여 일수에서 승인된 사용 일수를 뺀 값입니다. 추가 신청 가능한 일수는 여기에서 승인 대기 일수를 더 뺀 값입니다. 과거 기록이 새 자동 산정량보다 많더라도 기존 사용 기록을 삭제하거나 숨기지 않고 부족 일수를 표시합니다. 공휴일 자동 제외는 포함하지 않습니다. [근로기준법 제60조](https://www.law.go.kr/법령/근로기준법/제60조)의 일반 기준을 사용합니다.

휴가는 입사일 기준 한 기간 안에서 신청해야 합니다. 12월~1월 휴가도 같은 연차 기간 안이면 신청할 수 있습니다. 입사 기념일을 넘는 휴가는 기간별로 나누어 등록하세요.

## 데이터

직원과 휴가는 서버의 SQLite 파일에 저장되어 새로고침·서버 재시작 후에도 유지됩니다. 데이터 폴더와 빌드 결과, 설치된 패키지는 Git에서 제외됩니다. 실제 직원 정보를 입력하기 전에 가상 직원 자료와 분리해서 사용하세요. 실행 중인 데이터 파일을 임의로 삭제하지 마세요.

기본 파일은 `data/leave.sqlite`입니다. 가상 자료를 보존하면서 빈 데이터베이스에서 시작하려면 서버를 종료한 뒤 아래처럼 별도 파일을 지정하세요.

```sh
SEED_DEMO=0 DB_PATH=data/company.sqlite npm start
```

그 이후에도 같은 파일을 지정해야 저장된 실제 자료를 볼 수 있습니다. `SEED_DEMO=0`은 기존 자료를 삭제하지 않고, 빈 데이터베이스에 가상 자료를 넣는 동작만 끕니다. 개발 서버에도 같은 환경 변수를 사용할 수 있습니다.

선택 환경 변수: `DB_PATH`(SQLite 경로), `SEED_DEMO`(`0`이면 가상 데이터 생성 안 함), `PORT`(기본 3001), `HOST`(기본 `127.0.0.1`). 개발 모드의 API 프록시는 3001로 설정되어 있으므로 `npm run dev`에서는 기본 포트를 사용하세요. 이 관리자용 초기 버전은 기본 호스트를 유지하세요.

```sh

```

테스트는 별도의 임시 데이터베이스를 사용합니다. 실제 저장 자료에는 영향을 주지 않습니다.

## 클라우드 환경

각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용합니다. 별도 Git worktree는 필요하지 않습니다. 설치된 파일은 환경 게시 시 스냅샷에 포함되지만 실행 중인 서버 프로세스는 유지되지 않으므로 새 작업에서 `npm run dev` 또는 `npm start`로 다시 시작해야 합니다.
